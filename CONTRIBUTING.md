# Contributing to Memory Keel

Thank you for your interest in contributing! Memory Keel is a community-driven project — your experience and ideas make it better.

## Ways to Contribute

### Share Your Templates
The most valuable contribution is a template for a scenario we haven't covered. If you use Memory Keel for a workflow not in `examples/`, share it.

### Report Bugs
- Use the [Bug Report](https://github.com/polarislin19/Memory-Keel/issues/new?template=bug_report.md) template
- Describe what you expected and what happened
- Include your Memory Keel file structure (redact sensitive info)

### Suggest Features
- Use the [Feature Request](https://github.com/polarislin19/Memory-Keel/issues/new?template=feature_request.md) template
- Explain the use case — what problem are you trying to solve?

### Submit Pull Requests
1. Fork the repository
2. Create a branch: `git checkout -b feature/my-feature`
3. Make your changes
4. Test: does `scaffold.sh` still work? Are new files documented?
5. Commit with a clear message
6. Push and open a PR

### Documentation
Docs live in `docs/`. Improvements to clarity, new examples, and translations are all welcome.

## Style Guidelines

- Markdown files: use `##` for sections, keep lines wrapped at ~100 chars
- Shell scripts: POSIX-compatible, no bashisms
- Commit messages: imperative mood, present tense ("Add template" not "Added template")

## Code of Conduct

This project follows the [Contributor Covenant Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to uphold this code.
